Hallazgo Mas Critico

El sistema tiene dos backdoors de acceso admin funcionales y publicamente accesibles:

Backdoor #1

admin/api.php?action=login

Usuario: admin | Password: 1234 (texto plano)

Backdoor #2

api_admin_auth.php?action=login

Usuario: admin | Password: cardstudio2025 (en codigo fuente)

Ruta de ataque completa para ejecucion remota de codigo (RCE):

PASO 1: POST admin/api.php?action=login (user=admin&pass=1234) -> Respuesta: {"success": true} PASO 2: POST admin/api.php?action=save_design (imagen_fondo=@webshell.php) -> Archivo guardado: uploads/fondo_abc123.php PASO 3: GET admin/uploads/fondo_abc123.php -> CODIGO PHP EJECUTADO EN EL SERVIDOR

Resumen del stack actual: PHP vanilla sin framework, JavaScript vanilla sin modularizacion, MySQL con queries inline, zero tests, zero CI/CD, zero dependencias (sin Composer/npm).

2. Analisis de Seguridad

2.1 Vulnerabilidades Criticas

C1. Credenciales Admin Hardcodeadas
admin/api_admin_auth.php:14-15 | Hardcoded Credentials
La contrasena cardstudio2025 esta en texto plano en el codigo fuente. Aunque se aplica password_hash(), el valor original es visible para cualquiera que lea el archivo. El hash se recalcula en cada peticion HTTP (desperdicio de CPU).
C2. Backdoor de Login Admin con Credenciales en Texto Plano
admin/api.php:10-18 | Authentication Bypass
Segundo sistema de autenticacion completamente separado. Usa comparacion directa == con credenciales triviales: admin/1234. No usa sesiones, no usa hashing, no tiene rate limiting.
C3. API Publica Sin Autenticacion
api_publica.php:1-28 | Broken Access Control
Expone la tabla disenos completa incluyendo configuracion_textos_json con SELECT *. Cualquiera puede listar todos los disenos y ver su configuracion interna.
C4. Exposicion de Errores de Base de Datos
admin/api.php:119,134 | Information Disclosure
Los mensajes de error de MySQL se retornan directamente al cliente en JSON, revelando estructura de tablas, columnas y queries.
C5. Sin Autenticacion para CRUD Completo
admin/api.php:1-138 | Missing Authentication
Este archivo contiene operaciones CRUD (crear, editar, subir archivos) y NO tiene ninguna verificacion de sesion. Cualquiera puede crear/modificar disenos y subir archivos al servidor.

4.3 Problemas de Accesibilidad (WCAG)

Hallazgo: Se encontraron 0 (cero) atributos aria-* en todo el proyecto.
  • Modales: sin role="dialog", sin trap de foco, sin cierre con Escape
  • Canvas: sin role="img" ni aria-label alternativo
  • Formularios: labels sin for/id asociado
  • Contraste: texto #888 sobre fondo #1a1a1a = ratio ~3.5:1 (minimo WCAG AA: 4.5:1)
  • Navegacion: sidebar usa <div onclick> en vez de <button> o <a>

4.4 Problemas de UX

  • Auto-registro invisible: Al descargar sin cuenta, se crea automaticamente sin que el usuario lo sepa
  • alert() nativo en 15+ ubicaciones - rompe la experiencia visual premium
  • Sin loading states: la mayoria de paginas no muestra spinner al cargar datos
  • Logout inconsistente: 3 destinos diferentes segun la pagina
  • Placeholder con credenciales: login.html muestra placeholder="1234"

4.5 Performance

  • Imagenes sin optimizar: PNGs de 755 KB sin conversion a WebP
  • ~25 fuentes Google Fonts cargadas en el editor (mayoria sin usar)
  • Sin minificacion: ningun archivo CSS/JS esta minificado
  • innerHTML += en bucle: re-parsea todo el DOM en cada iteracion
  • CSS duplicado: index.html carga landing.css Y lo tiene inline
